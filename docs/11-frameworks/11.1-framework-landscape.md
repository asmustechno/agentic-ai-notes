## 🤔 Yeh kyun zaroori hai?

Priya ki team ek support agent ship karna chahti hai. Ek dopahar search karke use LangGraph, CrewAI, AutoGen, Microsoft Agent Framework, OpenAI Agents SDK, Claude Agent SDK, LlamaIndex aur Pydantic AI milte hain. Har home page "production-ready agents" ka wada karta hai. Har ek alag words use karta hai: graphs, crews, runners, harnesses, workflows.

Bina map ke, teams woh framework utha leti hain jiska naam pehle suna tha. Phir mahino tak usse ladti rehti hain. Map ho toh tum ek better sawal pooch sakte ho: *agent ke kaunse parts main kisi aur ke haath mein dena chahta hoon?*

Yeh chapter wahi map hai. Har framework page [1.5](../01-foundations/01.5-anatomy-of-an-agent.md) wala **same agent** dobara banata hai. Isliye tum barabar ki cheez ko barabar se compare karte ho.

## 🧠 Idea, simple words mein

[Agent framework](../../GLOSSARY.md#agent-framework) ek library hai jo [agent](../../GLOSSARY.md#agent) banane ke liye ready-made pieces deti hai. Jaise [agent loop](../../GLOSSARY.md#agent-loop), tumhare functions se bane [tool](../../GLOSSARY.md#tool) schemas, memory, tracing, aur kai agents ko saath kaam karwane ke tarike.

Socho tum kitchen bana rahe ho. Tum loose parts khareed ke khud fit kar sakte ho (provider SDK plus tumhara apna loop). Tum flat-pack units le sakte ho jo click karke jud jaate hain (ek agent SDK). Tum ek designer hire kar sakte ho jo plan kare ki poora kamra kaise flow karega (ek orchestration framework). Ya tum poora equipped kitchen kiraye par le ke bas khana bana sakte ho (ek harness).

Inme se koi bhi "best" nahi hai. Yeh is par depend karta hai ki tum kitna control chahte ho, aur kitna khud own karna chahte ho.

Neeche same agent ke paanch parts, har framework ke apne naamon ke saath:

| Part | LangGraph | CrewAI | Agent Framework | OpenAI Agents SDK | Claude Agent SDK | LlamaIndex | Pydantic AI |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ① Model | chat model (`init_chat_model`) | `LLM` | chat client | `model=` | `model=` (sirf Claude) | `llm=` | `model=` string |
| ② Instructions | tumhare node mein ek `SystemMessage` | role, goal, backstory + task | `instructions=` | `instructions=` | `system_prompt=` | `system_prompt=` | `instructions=` |
| ③ Tools | `@tool` | `@tool("name")` | plain functions | `@tool` | `@tool` + in-process MCP server | plain functions | `@agent.tool_plain` |
| ④ Memory | graph state + checkpointer | crew memory | `AgentSession` | sessions | sessions | memory / `Context` | message history |
| ⑤ Loop | edges jo tum draw karte ho | crew process | function invocation layer | `Runner` | Claude Code ka loop | `FunctionAgent` workflow | `agent.run` |

## 🔍 Kaise kaam karta hai, step by step

Framework koi bhi ho, ek run inhi steps se guzarta hai. Bas har framework alag steps apne haath mein leta hai.

1. **Tum tools describe karte ho.** Tum normal functions likhte ho. Framework naam, type hints aur docstrings padh ke woh [JSON Schema](../../GLOSSARY.md#json-schema) banata hai jo model ko chahiye ([3.2](../03-tools-and-function-calling/03.2-json-schema-for-tools.md)).
2. **Tum agent configure karte ho.** Model, instructions aur tools ek object mein jaate hain: `Agent`, `Crew`, `StateGraph` ya `ClaudeAgentOptions`.
3. **Framework loop chalata hai.** Woh model ko call karta hai, maange gaye tools chalata hai, results wapas bhejta hai aur repeat karta hai. Iski ek limit hoti hai (`max_turns`, `max_iter`, `recursion_limit`, `UsageLimits`).
4. **Jo hua woh record karta hai.** Zyada tar frameworks events ya [traces](../../GLOSSARY.md#trace) emit karte hain. Inhe tum print, test ya kisi tracing tool ko bhej sakte ho ([14.1](../14-observability-and-debugging/14.1-tracing-agent-runs.md)).
5. **Result return karta hai.** Usually final text, kabhi kabhi ek typed object (Pydantic AI, OpenAI Agents SDK), aur saath mein message history.

## 💡 Example se samjho

Is chapter ka har page [1.5](../01-foundations/01.5-anatomy-of-an-agent.md) ke ek task ke liye same agent banata hai: *"Is it warmer in Paris or Rome right now, and by how much?"* Isme ek fake `get_weather` hai (Paris 14 °C, Rome 19 °C, London 11 °C) aur ek safe `calculator`. Har page dikhata hai ki usko us framework ke apne [fake model](../../GLOSSARY.md#fake-model) se offline kaise chalao, jahan aisa model hai.

Offline chalane par har version same teen model calls aur same teen tool calls karta hai. Yeh raha Pydantic AI ka trace:

```text
tool call:   get_weather({"city":"Paris"})
tool call:   get_weather({"city":"Rome"})
tool result: {"city": "Paris", "temp_c": 14}
tool result: {"city": "Rome", "temp_c": 19}
tool call:   calculator({"expression":"19 - 14"})
tool result: 5

Answer: Rome is warmer: 19°C versus 14°C in Paris, a difference of 5°C.
```

Farak sirf is mein hai ki tum ise kaise likhte ho aur kaise test karte ho:

| Framework | Offline test double |
| --- | --- |
| [LangGraph](./11.2-langgraph.md) | `GenericFakeChatModel` subclass |
| [CrewAI](./11.3-crewai.md) | tumhara apna `BaseLLM` subclass |
| [AutoGen](./11.4-microsoft-autogen-and-agent-framework.md) (archived) | `ReplayChatCompletionClient` |
| [Microsoft Agent Framework](./11.4-microsoft-autogen-and-agent-framework.md) | tumhara apna `BaseChatClient` + `FunctionInvocationLayer` |
| [OpenAI Agents SDK](./11.5-openai-agents-sdk.md) | `agents.testing.ScriptedModel` |
| [Claude Agent SDK](./11.6-claude-agent-sdk.md) | koi nahi: Claude Code runtime aur ek key chahiye |
| [LlamaIndex](./11.7-llamaindex-agents.md) | `MockFunctionCallingLLM` |
| [Pydantic AI](./11.8-pydantic-ai.md) | `FunctionModel`, `TestModel` |

Har framework mein code lagbhag same size ka hai. Asli farak un concepts mein hai jo tumhe seekhne padte hain. Woh har page par dikhaye gaye hain.

## 💻 Code

Farak feel karne ka sabse jaldi tarika: ek hi tool ko kai frameworks mein define hote dekho. Function ki body same hai; sirf uske upar ka wrapping badalta hai.

```python
# Plain Python + provider SDK (11.9): schema tum khud likhte ho.
WEATHER_SPEC = {
    "name": "get_weather",
    "description": "Get the current temperature in °C for one city.",
    "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
}

# OpenAI Agents SDK (11.5) aur LangGraph (11.2): ek decorator type hints aur docstring padhta hai.
from agents.decorators import tool          # LangGraph: from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Get the current temperature in °C for one city.

    Args:
        city: City name, e.g. 'Paris'.
    """
    ...

# Pydantic AI (11.8): decorator tool ko ek agent par register bhi kar deta hai.
@agent.tool_plain
def get_weather(city: str) -> str: ...

# Microsoft Agent Framework (11.4) aur LlamaIndex (11.7): plain function pass karo.
agent = Agent(client=client, instructions=INSTRUCTIONS, tools=[get_weather, calculator])

# Claude Agent SDK (11.6): ek async handler jo MCP content blocks return karta hai.
@tool("get_weather", "Get the current temperature in °C for one city.", {"city": str})
async def get_weather(args: dict) -> dict:
    return {"content": [{"type": "text", "text": "..."}]}
```

## 🚨 Aam galtiyan aur dhyan dene wali baatein

- **Popularity dekh ke choose karna.** Stars attention naapte hain, fit nahi. Apni requirements se shuru karo (dekho [11.10](./11.10-how-to-choose.md)).
- **Purane tutorials par bharosa karna.** Yeh libraries bahut tezi se badalti hain: AutoGen archived hai, LangChain ne apne agent helpers shift kar diye, Pydantic AI major version 2 par hai. Dekho tutorial ne kaunsa version use kiya tha, aur apne versions pin karo.
- **Yeh maan lena ki "model-agnostic" matlab "koi farak nahi".** Structured output, hosted tools aur parallel tool calls jaise features provider ke hisaab se badalte hain, ek hi framework ke andar bhi. Usi model se test karo jo tum ship karoge.
- **Saare frameworks ek hi environment mein install karna.** Yeh bahut saare packages pin karte hain aur aapas mein conflict kar sakte hain. Har ek ko apna [virtual environment](../../GLOSSARY.md#virtual-environment) do.
- **Telemetry defaults bhool jaana.** Kuch frameworks default mein traces ya anonymous usage data bhejte hain (OpenAI Agents SDK tracing, CrewAI telemetry). Docs padho aur jahan zaroori ho wahan band karo.

## ✅ Yaad rakhne wali baatein

- Har framework wahi paanch parts package karta hai. Inhe pehchanna seekh lo, toh koi bhi framework aasaan lagega.
- Asli choice yeh hai ki tum kitna control saunpte ho: apna loop, ek agent SDK, ek orchestration framework, ya ek poora harness.
- Zyada tar frameworks offline tests ke liye ek fake model dete hain. Pehle din se use karo.
- AutoGen archived hai; Microsoft naye users ko Microsoft Agent Framework ki taraf bhejta hai.
- Versions pin karo aur docs dobara check karte raho: yeh landscape har mahine badalta hai.
