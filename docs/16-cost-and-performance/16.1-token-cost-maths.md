# 16.1 Token cost ka hisaab

> **Level:** 🟢 Beginner · **Padhne ka time:** ~10 min · **Pehle padho:** [1.4 LLMs kaise kaam karte hain (bas utna jitna zaroori hai)](../01-foundations/01.4-how-llms-work.md), [2.1 Observe–think–act loop](../02-the-agent-loop/02.1-the-observe-think-act-loop.md)

**Ek line mein:** Ek model call ka cost hota hai input tokens × input price plus output tokens × output price. Aur kyunki agent har step par poori conversation dobara bhejta hai, isliye ek run ka cost uske steps se kahin zyada tezi se badhta hai.

## 🤔 Yeh kyun zaroori hai?

Ek team apne research agent ko das sawalon par test karti hai. Har run mein lagbhag 5 steps lagte hain aur cost lagbhag 12 cents aata hai. Woh ek din mein 1,000 runs ka budget banate hain: $120.

Production mein asli sawal zyada mushkil hote hain. Runs 5 nahi, 20 steps lete hain. Team sochti hai ki bill chaar guna hoga. Lekin bill lagbhag nau guna ho jaata hai. Kyunki 20-step run, 5-step run se chaar guna se kahin zyada tokens bhejta hai.

Agar tumhe yeh maths aata hai, toh tum yeh pehle se predict kar sakte ho. Tum sahi limits laga sakte ho ([16.5](./16.5-budget-limits-per-run.md)). Aur tum dekh sakte ho ki is chapter ke kaun se levers (caching, routing, kam steps) sach mein bill kam karenge.

## 🧠 Idea, simple words mein

Providers har [token](../../GLOSSARY.md#token) ka paisa lete hain (ek token lagbhag ek English word ka ¾ hota hai). Price do tarah ka hota hai:

- **Input tokens**: jo kuch tum bhejte ho: [system prompt](../../GLOSSARY.md#system-prompt), tool definitions, ab tak ki conversation, tool results.
- **Output tokens**: jo kuch model likhta hai: text, tool calls, aur jo bhi thinking woh karta hai. Output ka per token price aam taur par input se kai guna zyada hota hai.

Claude ke prices, November 2026 ke hisaab se, US dollars per million tokens mein ([pricing page](https://platform.claude.com/docs/en/about-claude/pricing)):

| Model | Input | Output | Cache write (5 min) | Cache read |
| --- | --- | --- | --- | --- |
| Claude Opus 5.5 (`claude-opus-5-5`) | $4.00 | $20.00 | $5.00 | $0.20 |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | $2.00 | $10.00 | $2.50 | $0.10 |
| Claude Haiku 5.5 (`claude-haiku-5-5`), 100,000 tokens tak ke prompts | $0.10 | $0.50 | $0.125 | $0.01 |

(Cache prices [prompt caching](../../GLOSSARY.md#prompt-caching) ke liye hain, jo [16.2](./16.2-prompt-caching.md) mein cover hai. 100,000 tokens se bade prompts par Haiku 5.5 zyada charge karta hai.) OpenAI apne prices apne [pricing page](https://platform.openai.com/docs/pricing) par publish karta hai. Prices baar-baar badalte hain, isliye yeh book numbers copy karne ke bajaye placeholders use karti hai: `P_in` aur `P_out`. Copy kiye numbers jaldi purane ho jaate.

Agents ke liye sabse zaroori baat: **API stateless hai** ([1.4](../01-foundations/01.4-how-llms-work.md)). Har step par agent system prompt, tools aur *ab tak ki poori conversation* dobara bhejta hai. Step 10 phir se un sab ka paisa deta hai jo steps 1 se 9 ne joda tha. Isliye total input steps ki ginti ke lagbhag **square** ke hisaab se badhta hai.

Socho tum dost ko WhatsApp par voice note bhej rahe ho, lekin har naye message mein pichle saare voice notes bhi dobara attach karne padte hain. Pehla message chhota hai, dasvaan message bahut bhaari. Agent ke saath bhi bilkul yahi hota hai.

## 🔍 Kaise kaam karta hai, step by step

**1. Ek call ka cost:**

```text
cost = input_tokens × input_price / 1,000,000  +  output_tokens × output_price / 1,000,000
```

Claude Opus 5.5 par 2,000 tokens in aur 500 out: 2,000 × $4 / 1M + 500 × $20 / 1M = $0.008 + $0.010 = **$0.018**. Dhyan do: 500 output tokens ka cost 2,000 input tokens se zyada hai.

**2. Apne agent ke ek typical step ko** chaar numbers se describe karo (inhe apne traces se measure karo, [14.1](../14-observability-and-debugging/14.1-tracing-agent-runs.md)):

| Symbol | Matlab | Example |
| --- | --- | --- |
| `F` | Fixed prefix jo har call par jaata hai: system prompt + tool definitions + user ka goal | 3,100 |
| `O` | Har step ka output: model ki thinking, text aur tool call | 200 |
| `R` | Har step mein joda gaya tool result | 800 |
| `n` | Run mein kitne model calls hue | 10 |

**3. Poore run ko jodo.** Call *k* `F + (k − 1) × (O + R)` input tokens bhejta hai. *n* calls ka sum:

```text
total input  = n × F  +  (O + R) × n × (n − 1) / 2      ← the n² term is the resending
total output = n × O
```

(Upar `n²` wala term hi resending ka cost hai.)

**4. Prices se multiply karo,** phir per day ya per month ke runs se.

**5. Jo formula mein nahi aata, woh bhi jodo:** retries, fail hue runs jinka paisa phir bhi lagta hai, provider ke add kiye extra tokens (jab bhi tum tools pass karte ho, Anthropic kuch sau tokens ka tool-use system prompt add karta hai; Claude Opus 5.5 par automatic tool choice ke saath 286 tokens), aur lambe tool results.

## 💡 Example se samjho

[Chapter 14](../14-observability-and-debugging/README.md) wala order-support agent lo, jahan `F = 3,100`, `O = 200`, `R = 800`. Code section ka calculator alag-alag step counts par chalao, toh yeh milta hai:

```text
2) An agent loop: LoopShape(fixed=3000, goal=100, output=200, tool_result=800)
   steps   input tokens   output tokens   Opus 5.5   Sonnet 5.5   Haiku 5.5
       1          3,100             200     $0.016       $0.008     $0.0004
       5         25,500           1,000     $0.122       $0.061     $0.0031
      10         76,000           2,000     $0.344       $0.172     $0.0086
      20        252,000           4,000     $1.088       $0.544     $0.0272
      40        904,000           8,000     $3.776       $1.888     $0.0944

   Doubling the steps from 10 to 20 multiplies the Opus 5.5 cost by 3.2x, not 2x.

3) Where the 10-step run's input tokens come from
   fixed prefix resent 10 times:  31,000 (41%)
   growing history resent:        45,000 (59%)
```

10-step wali row haath se check karo:

- Input: 10 × 3,100 + 1,000 × 10 × 9 / 2 = 31,000 + 45,000 = **76,000** tokens.
- Output: 10 × 200 = **2,000** tokens.
- Opus 5.5 par cost: 76,000 × $4 / 1M + 2,000 × $20 / 1M = $0.304 + $0.040 = **$0.344**.

Table se chaar sabak:

1. **Steps sabse bhaari padte hain.** 5 → 20 steps matlab 4× steps aur lagbhag 9× cost ($0.122 → $1.088). Yahi woh kahani hai jo page ke shuru mein thi.
2. **Loop mein input hi bill ka bada hissa hai.** Output per token mehenga hai, lekin 10-step run output se 38 guna zyada input tokens bhejta hai. Isliye uske bill ka 88% input hai. Yahi wajah hai ki input ko cache karna ([16.2](./16.2-prompt-caching.md)) agents ke liye sabse bada single lever hai.
3. **Fixed prefix matter karta hai.** Input ka 41% wahi 3,100 tokens hain jo das baar bheje gaye. Lamba system prompt ya badi tool list har step par pay hoti hai.
4. **Model ka choice sab kuch scale karta hai.** Wahi run Haiku 5.5 par Opus 5.5 se 40× sasta hai, agar Haiku woh kaam kar sake ([16.3](./16.3-model-routing.md)).

Ek din mein 1,000 runs par, Opus 5.5 par 10-step run lagbhag $344 per day hai, yaani mahine ke lagbhag $10,300. OpenAI model ke liye bhi same token counts lagte hain; bas uske prices daal do: `76,000 × P_in / 1M + 2,000 × P_out / 1M`.

## 💻 Code

Calculator yeh raha:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Price:
    """Dollars per million tokens (har million tokens ka price)."""
    input: float
    output: float

PRICES = {  # November 2026, https://platform.claude.com/docs/en/about-claude/pricing
    "claude-opus-5-5": Price(4.00, 20.00),
    "claude-sonnet-5-5": Price(2.00, 10.00),
    "claude-haiku-5-5": Price(0.10, 0.50),   # 100,000 tokens tak ke prompts
}

def call_cost(price: Price, input_tokens: int, output_tokens: int) -> float:
    return (input_tokens * price.input + output_tokens * price.output) / 1_000_000

def loop_input_tokens(fixed: int, output: int, tool_result: int, steps: int) -> int:
    """Aise agent loop ke total input tokens jo har step par poori conversation dobara bhejta hai."""
    return steps * fixed + (output + tool_result) * steps * (steps - 1) // 2
```

Asli system mein estimate mat karo. Har response ke saath provider jo **usage return karta hai, woh padho** aur use har run ke liye jodo ([14.3](../14-observability-and-debugging/14.3-opentelemetry-for-llm-apps.md) wala trace yeh pehle se record karta hai):

```python
# Anthropic (Messages API)
resp = client.messages.create(model="claude-opus-5-5", max_tokens=16000, messages=messages)
cost = call_cost(PRICES["claude-opus-5-5"], resp.usage.input_tokens, resp.usage.output_tokens)
# resp.usage mein cache_read_input_tokens aur cache_creation_input_tokens bhi hain, jinka price alag hai (16.2),
# aur output_tokens_details.thinking_tokens: billed output tokens mein se kitne thinking the.

# OpenAI (Chat Completions): resp.usage.prompt_tokens aur resp.usage.completion_tokens
# OpenAI (Responses API):    resp.usage.input_tokens aur resp.usage.output_tokens
```

Prompt bhejne se *pehle* uske tokens ginne hain, toh provider ka token counter use karo (Anthropic: `client.messages.count_tokens(...)`). "4 characters per token" wala rough rule (offline tests ke liye [mock LLM](../../GLOSSARY.md#mockllm) mein kaam ka hai) curve ki shape dekhne ke liye theek hai. Bill ke liye kabhi nahi.

## 🚨 Aam galtiyan aur dhyan dene wali baatein

- **Ek call ka price nikaal ke step count se multiply kar dena.** Isme resending ignore ho jaati hai aur lambe runs ka cost bahut kam aanka jaata hai. **Fix:** loop wala formula use karo, ya usse bhi behtar, har run ka real usage jodo.
- **Thinking tokens bhool jaana.** Thinking on ho toh model ki reasoning output tokens mein bill hoti hai, chahe tum use dikhao ya nahi. **Fix:** usage field padho, visible text ki length nahi.
- **Har finished task ke bajaye har call ka cost measure karna.** Sasta model jise do retries ya teen extra steps chahiye, woh har *solved* task par zyada mehenga pad sakta hai. **Fix:** real traffic par har completed task ka cost compare karo.
- **Fixed prefix ko ignore karna.** 5,000 tokens ka system prompt plus 30 tool definitions har run ke har step par pay hote hain. **Fix:** use chhota karo, cache karo ([16.2](./16.2-prompt-caching.md)), aur tools sirf zaroorat par load karo.
- **Prices hard-code karna.** Prices badalte hain, aur alag platforms (Amazon Bedrock, Google Cloud Vertex AI) ki apni price lists hoti hain. **Fix:** prices ek config file mein rakho, saath mein woh date jab tumne check kiya.
- **Tier rules bhool jaana.** Prompt 100,000 tokens se upar jaate hi Claude Haiku 5.5 zyada charge karta hai, aur ek lamba agent run beech mein yeh line cross kar sakta hai. **Fix:** pricing page par apne model ke thresholds check karo.

## ✅ Yaad rakhne wali baatein

- Ek call ka cost = input tokens × input price + output tokens × output price; output (thinking mila ke) zyada mehenga hota hai.
- Agent har step par sab kuch dobara bhejta hai, toh total input ≈ `n × F + (O + R) × n(n − 1)/2`: yeh steps ke square ke saath badhta hai.
- Agent loops mein aam taur par bill ka bada hissa input hota hai, isiliye caching itni zaroori hai.
- Apne traces se har run ka real usage measure karo; models ko har completed task ke cost par compare karo.
