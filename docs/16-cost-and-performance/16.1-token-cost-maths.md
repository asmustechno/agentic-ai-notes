# 16.1 Token cost maths

> **Difficulty:** 🟢 Beginner · **Reading time:** ~10 min · **Prerequisites:** [1.4 How LLMs work (just enough)](../01-foundations/01.4-how-llms-work.md), [2.1 The observe-think-act loop](../02-the-agent-loop/02.1-the-observe-think-act-loop.md)

**In one sentence:** A model call costs its input tokens times the input price plus its output tokens times the output price, and because an agent resends the whole conversation on every step, the cost of a run grows much faster than its number of steps.

## 🤔 Why does this matter?

A team tests its research agent on ten questions. Each run takes about 5 steps and costs about 12 cents. They budget for 1,000 runs a day: $120.

In production, real questions are harder. Runs take 20 steps, not 5. The team expects the bill to quadruple. It goes up about nine times, because a 20-step run sends far more than four times the tokens of a 5-step run.

Knowing the maths lets you predict that before it happens, set sensible limits ([16.5](./16.5-budget-limits-per-run.md)), and see which of the levers in this chapter (caching, routing, fewer steps) will actually move the bill.

## 🧠 The idea, in plain words

Providers charge per [token](../../GLOSSARY.md#token) (roughly ¾ of an English word), in two prices:

- **Input tokens**: everything you send: the [system prompt](../../GLOSSARY.md#system-prompt), the tool definitions, the conversation so far, tool results.
- **Output tokens**: everything the model writes: text, tool calls, and any thinking it does. Output usually costs several times more per token than input.

Claude prices as of November 2026, in US dollars per million tokens ([pricing page](https://platform.claude.com/docs/en/about-claude/pricing)):

| Model | Input | Output | Cache write (5 min) | Cache read |
| --- | --- | --- | --- | --- |
| Claude Opus 5.5 (`claude-opus-5-5`) | $4.00 | $20.00 | $5.00 | $0.20 |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | $2.00 | $10.00 | $2.50 | $0.10 |
| Claude Haiku 5.5 (`claude-haiku-5-5`), prompts up to 100,000 tokens | $0.10 | $0.50 | $0.125 | $0.01 |

(Cache prices are for [prompt caching](../../GLOSSARY.md#prompt-caching), covered in [16.2](./16.2-prompt-caching.md). Haiku 5.5 costs more for prompts over 100,000 tokens.) OpenAI publishes its prices on its [pricing page](https://platform.openai.com/docs/pricing); prices change often, so this book uses placeholders, `P_in` and `P_out`, rather than copying numbers that will go out of date.

The key fact for agents: **the API is stateless** ([1.4](../01-foundations/01.4-how-llms-work.md)). On every step, the agent resends the system prompt, the tools and *the whole conversation so far*. Step 10 pays again for everything steps 1 to 9 added. That makes the total input grow with roughly the **square** of the number of steps.

## 🔍 How it works, step by step

**1. Cost of one call:**

```text
cost = input_tokens × input_price / 1,000,000  +  output_tokens × output_price / 1,000,000
```

2,000 tokens in and 500 out on Claude Opus 5.5: 2,000 × $4 / 1M + 500 × $20 / 1M = $0.008 + $0.010 = **$0.018**. Notice that the 500 output tokens cost more than the 2,000 input tokens.

**2. Describe a typical step** of your agent with four numbers (measure them from your traces, [14.1](../14-observability-and-debugging/14.1-tracing-agent-runs.md)):

| Symbol | Meaning | Example |
| --- | --- | --- |
| `F` | Fixed prefix sent on every call: system prompt + tool definitions + the user's goal | 3,100 |
| `O` | Output per step: the model's thinking, text and tool call | 200 |
| `R` | Tool result added per step | 800 |
| `n` | Number of model calls in the run | 10 |

**3. Add up the run.** Call *k* sends `F + (k − 1) × (O + R)` input tokens. Summing over *n* calls:

```text
total input  = n × F  +  (O + R) × n × (n − 1) / 2      ← the n² term is the resending
total output = n × O
```

**4. Multiply by the prices,** then by the number of runs per day or month.

**5. Add what the formula leaves out:** retries, failed runs you still pay for, extra tokens the provider adds (Anthropic adds a tool-use system prompt of a few hundred tokens whenever you pass tools; 286 tokens on Claude Opus 5.5 with automatic tool choice), and long tool results.

## 💡 Worked example

The order-support agent from [chapter 14](../14-observability-and-debugging/README.md), with `F = 3,100`, `O = 200`, `R = 800`. Running the calculator from the Code section over a range of step counts gives:

```text
2) An agent loop: LoopShape(fixed=3000, goal=100, output=200, tool_result=800)
   steps   input tokens   output tokens   Opus 5.5   Sonnet 5.5   Haiku 5.5
       1          3,100             200     $0.016       $0.008     $0.0004
       5         25,500           1,000     $0.122       $0.061     $0.0031
      10         76,000           2,000     $0.344       $0.172     $0.0086
      20        252,000           4,000     $1.088       $0.544     $0.0272
      40        904,000           8,000     $3.776       $1.888     $0.0944

   Doubling the steps from 10 to 20 multiplies the Opus 5.5 cost by 3.2x, not 2x.

3) Where the 10-step run's input tokens come from
   fixed prefix resent 10 times:  31,000 (41%)
   growing history resent:        45,000 (59%)
```

Check the 10-step row by hand:

- Input: 10 × 3,100 + 1,000 × 10 × 9 / 2 = 31,000 + 45,000 = **76,000** tokens.
- Output: 10 × 200 = **2,000** tokens.
- Cost on Opus 5.5: 76,000 × $4 / 1M + 2,000 × $20 / 1M = $0.304 + $0.040 = **$0.344**.

Four lessons from the table:

1. **Steps dominate.** 5 → 20 steps is 4× the steps and about 9× the cost ($0.122 → $1.088). This is the story from the top of the page.
2. **In a loop, input dominates.** Output is pricier per token, but the 10-step run sends 38 times as many input tokens as output tokens, so input is 88% of its bill. That is why caching the input ([16.2](./16.2-prompt-caching.md)) is the biggest single lever for agents.
3. **The fixed prefix matters.** 41% of the input is the same 3,100 tokens sent ten times. A long system prompt or a big tool list is paid on every step.
4. **Model choice scales everything.** The same run costs 40× less on Haiku 5.5 than on Opus 5.5, if Haiku can do the job ([16.3](./16.3-model-routing.md)).

At 1,000 runs a day, the 10-step run on Opus 5.5 is about $344 a day, or roughly $10,300 a month. For an OpenAI model, the same token counts apply; plug in its prices: `76,000 × P_in / 1M + 2,000 × P_out / 1M`.

## 💻 Code

The calculator:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Price:
    """Dollars per million tokens."""
    input: float
    output: float

PRICES = {  # November 2026, https://platform.claude.com/docs/en/about-claude/pricing
    "claude-opus-5-5": Price(4.00, 20.00),
    "claude-sonnet-5-5": Price(2.00, 10.00),
    "claude-haiku-5-5": Price(0.10, 0.50),   # prompts up to 100,000 tokens
}

def call_cost(price: Price, input_tokens: int, output_tokens: int) -> float:
    return (input_tokens * price.input + output_tokens * price.output) / 1_000_000

def loop_input_tokens(fixed: int, output: int, tool_result: int, steps: int) -> int:
    """Total input tokens of an agent loop that resends the whole conversation each step."""
    return steps * fixed + (output + tool_result) * steps * (steps - 1) // 2
```

In a real system, do not estimate: **read the usage the provider returns** on every response and add it up per run (the trace from [14.3](../14-observability-and-debugging/14.3-opentelemetry-for-llm-apps.md) already records it):

```python
# Anthropic (Messages API)
resp = client.messages.create(model="claude-opus-5-5", max_tokens=16000, messages=messages)
cost = call_cost(PRICES["claude-opus-5-5"], resp.usage.input_tokens, resp.usage.output_tokens)
# resp.usage also has cache_read_input_tokens and cache_creation_input_tokens, priced separately (16.2),
# and output_tokens_details.thinking_tokens: how many of the billed output tokens were thinking.

# OpenAI (Chat Completions): resp.usage.prompt_tokens and resp.usage.completion_tokens
# OpenAI (Responses API):    resp.usage.input_tokens and resp.usage.output_tokens
```

To count a prompt's tokens *before* you send it, use the provider's token counter (Anthropic: `client.messages.count_tokens(...)`). The rough "4 characters per token" rule (handy in a [mock LLM](../../GLOSSARY.md#mockllm) for offline tests) is fine for the shape of a curve, never for a bill.

## 🚨 Common mistakes & gotchas

- **Pricing one call and multiplying by the step count.** That ignores the resending and under-estimates long runs badly. **Fix:** use the loop formula, or better, sum real usage per run.
- **Forgetting thinking tokens.** With thinking on, the model's reasoning is billed as output tokens even when you don't display it. **Fix:** read the usage field, not the length of the visible text.
- **Measuring cost per call instead of per finished task.** A cheaper model that needs two retries, or three extra steps, can cost more per *solved* task. **Fix:** compare cost per completed task on real traffic.
- **Ignoring the fixed prefix.** A 5,000-token system prompt plus 30 tool definitions is paid on every step of every run. **Fix:** trim it, cache it ([16.2](./16.2-prompt-caching.md)), and load tools only when needed.
- **Hard-coding prices.** They change, and different platforms (Amazon Bedrock, Google Cloud Vertex AI) have their own price lists. **Fix:** keep prices in one config file with the date you checked them.
- **Forgetting tier rules.** Claude Haiku 5.5 charges more once a prompt goes over 100,000 tokens, and a long agent run can cross that line part-way through. **Fix:** check the pricing page for thresholds that apply to your model.

## ✅ Key takeaways

- Cost of a call = input tokens × input price + output tokens × output price; output (including thinking) is the more expensive kind.
- An agent resends everything every step, so total input ≈ `n × F + (O + R) × n(n − 1)/2`: it grows with the square of the steps.
- In agent loops, input usually dominates the bill, which is why caching matters so much.
- Measure real usage per run from your traces; compare models on cost per completed task.
