## 🤔 Yeh kyun zaroori hai?

Agent frameworks bahut saare alag-alag naam use karte hain: crews, graphs, runners, handoffs, toolkits. Andar se sab wahi paanch parts jodte hain. Jab tumhe yeh parts dikhne lagte hain, toh teen cheezein aasan ho jaati hain:

- **Framework seekhna.** Naya vocabulary ratne ki jagah tum poochhte ho "tools kahan jaate hain? loop kahan hai?"
- **Debugging.** Galat jawab aam taur par kisi ek part ki problem hota hai: ek vague instruction, ek badly described tool, missing memory, ya ek loop jo bahut jaldi ruk gaya.
- **Designing.** Defaults maan lene ki jagah tum har part soch-samajh ke decide kar sakte ho.

## 🧠 Idea, simple words mein

Wapas chalo [1.1](./01.1-what-is-an-ai-agent.md) wale naye intern ke paas:

| Part | Intern | Agent |
| --- | --- | --- |
| ① **Model** | Uska dimaag: padhna, sochna, decide karna | LLM |
| ② **Instructions** | Pehle din ki briefing: role, goals, rules | System prompt |
| ③ **Tools** | Un systems ke logins jo woh use kar sakta hai | Functions jinhe chalane ko model tumse keh sakta hai |
| ④ **Memory** | Uski notebook (aaj ka kaam) aur company wiki (jo pehle se pata hai) | Ab tak ki conversation, plus stored facts aur documents |
| ⑤ **Loop** | "Try karo, check karo, phir try karo" ki aadat, jab tak kaam na ho jaaye | Code jo think → act → observe repeat karta hai, limits ke saath |

Pehle chaar parts woh hain jo agent ke *paas hain*. Loop woh hai jo agent *karta hai*. Loop ke bina tumhare paas kuch extras wala ek model hai. Loop ke saath, tumhare paas ek agent hai.

## 🔍 Kaise kaam karta hai, step by step

**① Model.** Woh [LLM](../../GLOSSARY.md#large-language-model-llm) jo context padhta hai aur agla step decide karta hai. Model chunna capability, speed aur cost ke beech ka trade hai. Bahut saare production systems ek se zyada model use karte hain: mushkil decisions ke liye ek capable model, aur simple steps ke liye ek chhota model ([16.3](../16-cost-and-performance/16.3-model-routing.md)).

**② [Instructions](../../GLOSSARY.md#instructions).** Aam taur par [system prompt](../../GLOSSARY.md#system-prompt). Achhi instructions batati hain: agent ka role, uska goal, kaunse rules follow karne hain, tools kaise use karne hain, aur kab rukna hai ya help maangni hai. Vague instructions ajeeb agent behaviour ki sabse common wajah hain.

**③ Tools.** Har [tool](../../GLOSSARY.md#tool) ek normal function hai, plus ek description jo model padhta hai: ek naam, woh kya karta hai, aur uske inputs ka JSON Schema. Model sirf description dekhta hai, tumhara code kabhi nahi. Isliye description interface ka hissa hai. Chapter 03 poora tools ke baare mein hai.

**④ Memory.** Do tarah ki:

- *[Short-term](../../GLOSSARY.md#short-term-memory):* current run ki conversation, har tool call aur result ke saath. Yeh context window mein rehti hai ([1.4](./01.4-how-llms-work.md)).
- *[Long-term](../../GLOSSARY.md#long-term-memory):* jo kuch runs ke beech rakha jaata hai, jaise user preferences, pichle outcomes ya documents. Tumhara code ise store karta hai aur zaroorat padne par relevant hisse wapas context mein daalta hai. Chapters 05 aur 06 ise cover karte hain.

**⑤ Loop.** [Agent loop](../../GLOSSARY.md#agent-loop): woh control code jo model ko call karta hai, maange gaye tools chalata hai, results memory mein jodta hai aur repeat karta hai. Yeh limits (steps, time, cost) bhi lagata hai aur errors handle karta hai. Chapter 02 ise theek se banata hai.

Socho ek cricket team. Captain (model) faisle leta hai. Coach ka game plan (instructions) batata hai ki kaise khelna hai. Bowlers aur fielders (tools) asli kaam karte hain. Scoreboard (memory) batata hai ab tak kya hua. Aur over-by-over khel (loop) tab tak chalta hai jab tak match khatam na ho. Har haar ka dosh captain par daalna aasan hai, lekin kabhi-kabhi problem game plan ya fielding mein hoti hai.

## 💡 Example se samjho

Do tools wala ek travel assistant. Usse poochha gaya *"Abhi Paris zyada garam hai ya Rome, aur kitna?"*

```text
step 1: get_weather({'city': 'Paris'}) -> {"city": "Paris", "temp_c": 14}
step 1: get_weather({'city': 'Rome'}) -> {"city": "Rome", "temp_c": 19}
step 2: calculator({'expression': '19 - 14'}) -> 5
step 3: answer

Answer: Rome is warmer: 19°C versus 14°C in Paris, a difference of 5°C.
```

Is run ko paanch parts se jodo:

| Kya hua | Part |
| --- | --- |
| System prompt ne kaha *"use get_weather for real temperatures, never guess"* aur *"use calculator for arithmetic"* | ② Instructions |
| Step 1 mein model ne **dono** cities ek saath maangi, do tool calls ki tarah | ① Model, ③ Tools |
| Temperatures wapas aaye aur conversation mein add hue | ④ Short-term memory |
| Stored facts se *"Prefers temperatures in Celsius"* daala gaya | ④ Long-term memory |
| Model ne dono results dekhe, phir calculator chuna, phir rukna chuna | ⑤ Loop |

## 💻 Code

Ek chhoti `Agent` class, jisme har part label kiya hua hai. `model` koi bhi chat-model client hai ([1.1](./01.1-what-is-an-ai-agent.md#-code) ki tarah), aur `user()` aur `tool_result()` bas message dicts banate hain:

```python
@dataclass
class Agent:
    model: Any                                         # ① MODEL
    instructions: str                                  # ② INSTRUCTIONS (system prompt)
    tools: dict[str, tuple[Callable[..., str], dict]]  # ③ TOOLS: function + description
    facts: list[str] = field(default_factory=list)     # ④ MEMORY (long-term)
    max_steps: int = 6                                 # ⑤ LOOP ki limit

    def run(self, goal: str) -> str:
        messages = [user(goal)]                        # ④ MEMORY (short-term)
        system = self.instructions + "".join(f"\n- {f}" for f in self.facts)
        specs = [spec for _, spec in self.tools.values()]

        for _ in range(self.max_steps):                # ⑤ LOOP
            reply = self.model.chat(messages, system=system, tools=specs)  # ① socho
            messages.append(reply.to_message())
            if not reply.tool_calls:
                return reply.text                      # model ne rukna chuna
            for call in reply.tool_calls:              # ③ act karo
                fn, _ = self.tools[call.name]
                messages.append(tool_result(call.id, fn(**call.arguments)))  # ④ observe karo
        return "I could not finish within the step limit."
```

Tool ek plain function hai, plus uski description:

```python
WEATHER_SPEC = {
    "name": "get_weather",
    "description": "Get the current temperature in °C for one city.",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "City name, e.g. 'Paris'."}},
        "required": ["city"],
    },
}
```

## 🚨 Aam galtiyan aur dhyan dene wali baatein

- **Sabse pehle model ko dosh dena.** Zyada tar failures baaki chaar parts se aate hain: unclear instructions, misleading tool description, missing context, ya koi step limit nahi. Model badalne se pehle inhe check karo.
- **Tool descriptions insaanon ke liye likhna, model ke liye nahi.** Model sirf utna jaanta hai jitna description kehti hai. "Gets data" bekaar hai; "Get the current temperature in °C for one city" clear hai. [3.4](../03-tools-and-function-calling/03.4-designing-good-tools.md) dekho.
- **Bahut zyada tools.** Har tool description context mein jagah leti hai, aur model ko galat chunne ka ek aur tarika deti hai. Sirf utne tools se shuru karo jitne chahiye.
- **Memory ko "sab kuch store karo" samajhna.** Zyada context hamesha behtar nahi hota: irrelevant history model ka dhyan bhatkati hai aur paisa bhi khaati hai. Decide karo ki kya rakhna hai ([5.5](../05-memory/05.5-memory-design-trade-offs.md)).
- **Bina limits ya error handling ka loop.** Ek fail hota tool ya ek confused model hamesha ke liye loop kar sakta hai. [2.4](../02-the-agent-loop/02.4-stopping-conditions.md) aur [2.5](../02-the-agent-loop/02.5-handling-errors-in-the-loop.md) dekho.

## ✅ Yaad rakhne wali baatein

- Paanch parts: ① model, ② instructions, ③ tools, ④ memory, ⑤ loop.
- Pehle chaar woh hain jo agent ke paas hain; loop woh hai jo use agent banata hai.
- Model sirf tool *descriptions* dekhta hai, isliye woh tumhare interface ka hissa hain.
- Memory short-term hai (is run ki conversation) aur long-term (runs ke beech stored).
- Debugging karte waqt har part ek-ek kar ke check karo; problem shayad hi kabhi "sirf model" hoti hai.

## 🧪 Khud try karo

1. Upar wala `Agent` bina `facts` ke banao (default khaali list), `facts=["Prefers temperatures in Celsius"]` ki jagah. Model ko milne wale system prompt mein kya badalta hai?
2. Ek "meeting room book karo" agent ke liye, paanchon parts mein se har ek ka ek item likho.

<details>
<summary>Answer dekho</summary>

1. Instructions ke baad `- Prefers temperatures in Celsius` wali line ab add nahi hoti, toh model ko woh preference pata hi nahi. Long-term memory model tak sirf context ke through pahunchti hai.
2. Ek possible jawab. ① Model: ek fast, mid-sized LLM. ② Instructions: "You book rooms for staff. Confirm the time and size before booking. Never double-book." ③ Tools: `find_free_rooms(start, end, capacity)`, `book_room(room_id, start, end)`. ④ Memory: conversation (short-term), user ka usual office aur team size (long-term). ⑤ Loop: zyada se zyada 8 steps; booking confirm hote hi ya user cancel kare toh ruk jao.
