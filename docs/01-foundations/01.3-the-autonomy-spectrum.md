# 1.3 The autonomy spectrum

> **Difficulty:** 🟢 Beginner · **Reading time:** ~7 min · **Prerequisites:** [1.2 Chatbot vs workflow vs agent](./01.2-chatbot-vs-workflow-vs-agent.md)

**In one sentence:** "Agent or not" is really a sliding scale of how much control the model has over what happens next, and you should pick the lowest level that solves your problem.

## 🤔 Why does this matter?

The previous page sorted systems into three boxes. Real systems don't always fit neatly. Is a system that asks the model "is this billing or technical?" and then follows a fixed path an agent? What about one that lets the model call a single tool once?

Arguing over labels wastes time. A better question is: **how much does the model decide?** Each step up gives you more flexibility and costs you predictability, money and ease of testing. Seeing it as a scale makes that trade-off visible.

## 🧠 The idea, in plain words

Self-driving cars are often described with levels, from "the driver does everything" to "the car drives itself anywhere" ([SAE J3016](https://www.sae.org/standards/content/j3016_202104/)). The [autonomy spectrum](../../GLOSSARY.md#autonomy-spectrum) for LLM systems works the same way: at each level, the model takes over one more decision from your code.

The levels below are our own framing, inspired by the "agency levels" in the [Hugging Face smolagents docs](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents). Other authors draw the lines slightly differently; the idea of a gradual scale is what matters.

## 🔍 How it works, step by step

| Level | Name | What the model decides | Example |
| --- | --- | --- | --- |
| **0** | Single prompt | Only the words of its reply | "Summarise this article." |
| **1** | Fixed workflow | Only the words at each fixed step | Write an outline, then a draft, then a title |
| **2** | Router | Which branch the code takes | "Is this email billing or technical?" then a fixed handler |
| **3** | Tool call | Which function to run, and with what arguments | Turn "weather in Paris?" into `get_weather(city="Paris")`, once |
| **4** | Agent loop | Whether to keep going, what to do next, when to stop | Look up an order, then tracking, then answer |
| **5** | Autonomous | Its own sub-goals, over a long time, with little oversight | "Fix all the failing tests in this repository" |

Two things change as you move right:

1. **The model makes more decisions,** so there are more places for it to be wrong. A small error rate per decision adds up over many decisions ([1.6](./01.6-when-not-to-use-an-agent.md) does the maths).
2. **You need more safety around it:** step limits, budgets, approvals for risky actions, logging, and evaluation. Level 5 systems need all of chapters 12–16.

Levels 4 and 5 are what these notes call [agents](../../GLOSSARY.md#agent). Levels 0–3 are [workflows](../../GLOSSARY.md#workflow), even though they use an LLM. Chapter 09 covers the workflow patterns (chaining, routing, parallelisation) in depth.

## 💡 Worked example

A company wants to help staff with expense claims. Here is the same feature at each level:

- **Level 0:** a button that rewrites a claim description to be clearer.
- **Level 1:** extract the amount, date and merchant from a receipt photo, then fill in a form. Same steps every time.
- **Level 2:** the model classifies the expense as travel, meals or equipment; each category has its own fixed approval rules.
- **Level 3:** the model reads "lunch with a client in Berlin, €48" and calls `convert_currency(amount=48, from="EUR", to="GBP")`.
- **Level 4:** "Why was my claim rejected?" The model looks up the claim, reads the policy, checks the approver's comment and explains, choosing each step from what it found.
- **Level 5:** an agent that audits every claim for the quarter, investigates anything unusual on its own and drafts a report.

Most teams get most of the value at levels 1–3. Level 4 is worth it for the open-ended "why" questions. Level 5 needs strong evidence that it works, and human review of its output.

## 💻 Code

Levels 2, 3 and 4 differ by only a few lines. As in [1.1](./01.1-what-is-an-ai-agent.md#-code), `llm` is any chat-model client:

```python
# user(text) and tool_result(call_id, content) just build message dicts,
# e.g. {"role": "user", "content": text}.

# Level 2: router. The model picks a label; code picks the path.
label = llm.chat([user(f"Reply with one word, billing or technical: {email}")]).text.strip().lower()
handler = billing_team if label == "billing" else technical_team
handler(email)

# Level 3: one tool call. The model picks the function and arguments, once.
reply = llm.chat([user(question)], tools=TOOL_SPECS)
call = reply.tool_calls[0]
answer = TOOLS[call.name](**call.arguments)

# Level 4: agent loop. The model also decides whether to continue.
messages = [user(question)]
while True:                                  # (always add a step limit in real code)
    reply = llm.chat(messages, tools=TOOL_SPECS)
    messages.append(reply.to_message())
    if not reply.tool_calls:
        break                                # the model decided it is done
    for call in reply.tool_calls:
        messages.append(tool_result(call.id, TOOLS[call.name](**call.arguments)))
```

The step from level 3 to level 4 is just wrapping the call in a loop and feeding results back, yet it changes who is in control.

## 🚨 Common mistakes & gotchas

- **Starting at level 4 or 5 because it sounds impressive.** Every level up adds cost, latency and new ways to fail. Start low and move up only when you can show the lower level isn't good enough.
- **Trusting the level 2 label blindly.** In the router above, a reply of "Billing." or "It's billing" would go to the wrong team. Validate model output before you branch on it; [structured output](../03-tools-and-function-calling/03.2-json-schema-for-tools.md) helps.
- **Level 3 code that assumes a tool call always comes back.** The model may answer in text instead. Check `reply.tool_calls` before using it.
- **Level 5 with level 1 safety.** Long-running autonomous agents need budgets, sandboxes, approvals and monitoring before they touch anything real.

## ✅ Key takeaways

- Autonomy is a scale, not a yes/no. The question is *how much does the model decide?*
- Levels 0–3 are workflows (code controls the path); levels 4–5 are agents (the model controls the path).
- Each level up trades predictability, cost and testability for flexibility.
- Pick the lowest level that solves your problem, and move up only with evidence.
