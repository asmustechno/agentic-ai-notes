## 🤔 Yeh kyun zaroori hai?

Pichle page ne systems ko teen dabbon mein baanta tha. Real systems hamesha saaf-saaf fit nahi hote.

Ek system jo model se poochhta hai "yeh billing ka hai ya technical?" aur phir ek fixed path follow karta hai, kya woh agent hai? Aur woh system jo model ko ek hi tool sirf ek baar call karne deta hai?

Labels par behas karna time ki barbaadi hai. Behtar sawal hai: **model kitna decide karta hai?** Har step upar jaane par flexibility milti hai, lekin predictability, paisa aur testing ki aasani jaati hai. Ise ek scale ki tarah dekhne se yeh trade-off saaf dikhta hai.

## 🧠 Idea, simple words mein

Self-driving cars ko aksar levels mein describe kiya jaata hai, "driver sab kuch karta hai" se le kar "car kahin bhi khud chalti hai" tak ([SAE J3016](https://www.sae.org/standards/content/j3016_202104/)). LLM systems ka [autonomy spectrum](../../GLOSSARY.md#autonomy-spectrum) bhi aise hi kaam karta hai. Har level par model tumhare code se ek aur decision apne haath mein le leta hai.

Neeche wale levels hamari apni framing hain, [Hugging Face smolagents docs](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents) ke "agency levels" se inspired. Doosre authors lines thodi alag kheenchte hain. Asli baat hai dheere-dheere badhne wale scale ka idea.

Ghar ka budget socho. Level 0: bachche ko sirf list padh ke sunani hai. Level 2: woh decide karta hai ki doodh wale ke paas jaana hai ya kirana dukaan. Level 4: use paise de diye, ab woh khud dekhta hai kya khatam hai, kya laana hai, aur kab ghar wapas aana hai. Har level par zyada bharosa chahiye, aur zyada hisaab-kitaab bhi.

*Ise baayein se daayein padho. Har level par model ek aur aisa decision leta hai jo pehle tumhara code leta tha. Workflows aur agents ke beech ki line wahan padti hai jahan model decide karne lagta hai ki kab rukna hai.*

## 🔍 Kaise kaam karta hai, step by step

| Level | Naam | Model kya decide karta hai | Example |
| --- | --- | --- | --- |
| **0** | Single prompt | Sirf apne reply ke words | "Summarise this article." |
| **1** | Fixed workflow | Sirf har fixed step ke words | Pehle outline likho, phir draft, phir title |
| **2** | Router | Code kaunsi branch lega | "Is this email billing or technical?" phir ek fixed handler |
| **3** | Tool call | Kaunsa function chalana hai, aur kin arguments ke saath | "weather in Paris?" ko `get_weather(city="Paris")` mein badalna, ek baar |
| **4** | Agent loop | Aage badhna hai ya nahi, aage kya karna hai, kab rukna hai | Order dekho, phir tracking, phir jawab do |
| **5** | Autonomous | Apne khud ke sub-goals, lambe time tak, kam nigraani ke saath | "Fix all the failing tests in this repository" |

Daayein jaate hue do cheezein badalti hain:

1. **Model zyada decisions leta hai,** toh uske galat hone ki jagahein bhi zyada hain. Har decision par chhota sa error rate bhi bahut saare decisions mein jud ke bada ho jaata hai ([1.6](./01.6-when-not-to-use-an-agent.md) iska hisaab karta hai).
2. **Uske aaspaas zyada safety chahiye:** step limits, budgets, risky actions ke liye approvals, logging, aur evaluation. Level 5 systems ko chapters 12–16 ka sab kuch chahiye.

Levels 4 aur 5 ko yeh notes [agents](../../GLOSSARY.md#agent) kehte hain. Levels 0–3 [workflows](../../GLOSSARY.md#workflow) hain, chahe woh LLM use karte hon. Chapter 09 workflow patterns (chaining, routing, parallelisation) ko detail mein cover karta hai.

## 💡 Example se samjho

Ek company apne staff ki expense claims mein help karna chahti hai. Yeh raha wahi feature har level par:

- **Level 0:** ek button jo claim description ko zyada clear bana ke dobara likh deta hai.
- **Level 1:** receipt ki photo se amount, date aur merchant nikalo, phir ek form bharo. Har baar same steps.
- **Level 2:** model expense ko travel, meals ya equipment mein classify karta hai; har category ke apne fixed approval rules hain.
- **Level 3:** model "lunch with a client in Berlin, €48" padhta hai aur `convert_currency(amount=48, from="EUR", to="GBP")` call karta hai.
- **Level 4:** "Mera claim reject kyun hua?" Model claim dhoondhta hai, policy padhta hai, approver ka comment check karta hai aur samjhata hai. Har step woh usi se chunta hai jo use mila.
- **Level 5:** ek agent jo quarter ke har claim ka audit karta hai, kuch bhi ajeeb dikhe toh khud investigate karta hai, aur ek report draft karta hai.

Zyada tar teams ko zyada tar value levels 1–3 par hi mil jaati hai. Open-ended "kyun" wale sawalon ke liye level 4 worth it hai. Level 5 ke liye strong evidence chahiye ki woh kaam karta hai, aur uske output ka human review bhi.

## 💻 Code

Levels 2, 3 aur 4 mein sirf kuch lines ka farak hai. [1.1](./01.1-what-is-an-ai-agent.md#-code) ki tarah, `llm` koi bhi chat-model client hai:

```python
# user(text) aur tool_result(call_id, content) bas message dicts banate hain,
# jaise {"role": "user", "content": text}.

# Level 2: router. Model label chunta hai; code path chunta hai.
label = llm.chat([user(f"Reply with one word, billing or technical: {email}")]).text.strip().lower()
handler = billing_team if label == "billing" else technical_team
handler(email)

# Level 3: ek tool call. Model function aur arguments chunta hai, ek baar.
reply = llm.chat([user(question)], tools=TOOL_SPECS)
call = reply.tool_calls[0]
answer = TOOLS[call.name](**call.arguments)

# Level 4: agent loop. Model yeh bhi decide karta hai ki aage chalna hai ya nahi.
messages = [user(question)]
while True:                                  # (real code mein hamesha step limit lagao)
    reply = llm.chat(messages, tools=TOOL_SPECS)
    messages.append(reply.to_message())
    if not reply.tool_calls:
        break                                # model ne decide kiya ki kaam ho gaya
    for call in reply.tool_calls:
        messages.append(tool_result(call.id, TOOLS[call.name](**call.arguments)))
```

Level 3 se level 4 tak ka step bas itna hai: call ko ek loop mein lapeto aur results wapas do. Phir bhi isse badal jaata hai ki control kiske haath mein hai.

## 🚨 Aam galtiyan aur dhyan dene wali baatein

- **Level 4 ya 5 se shuru karna kyunki woh impressive lagta hai.** Har level upar cost, latency aur fail hone ke naye tarike jodta hai. Neeche se shuru karo, aur upar tabhi jao jab dikha sako ki neecha level kaafi nahi hai.
- **Level 2 ke label par aankh band kar ke bharosa karna.** Upar wale router mein "Billing." ya "It's billing" jaisa reply galat team ke paas chala jaayega. Model output par branch karne se pehle use validate karo; [structured output](../03-tools-and-function-calling/03.2-json-schema-for-tools.md) help karta hai.
- **Level 3 ka aisa code jo maan leta hai ki tool call hamesha aayega.** Model shayad text mein jawab de de. Use karne se pehle `reply.tool_calls` check karo.
- **Level 5 ke saath level 1 wali safety.** Lambe time chalne wale autonomous agents ko kisi bhi real cheez ko chhoone se pehle budgets, sandboxes, approvals aur monitoring chahiye.

## ✅ Yaad rakhne wali baatein

- Autonomy ek scale hai, haan/naa nahi. Sawal hai: *model kitna decide karta hai?*
- Levels 0–3 workflows hain (path code control karta hai); levels 4–5 agents hain (path model control karta hai).
- Har level upar jaane par predictability, cost aur testability ke badle flexibility milti hai.
- Sabse neecha level chuno jo tumhari problem solve kare, aur upar sirf evidence ke saath jao.
