# 5.1 Short-term vs long-term memory

> **Level:** 🟢 Beginner · **Padhne ka time:** ~8 min · **Pehle padho:** [1.4 LLMs kaise kaam karte hain (bas utna jitna zaroori hai)](../01-foundations/01.4-how-llms-work.md), [1.5 Agent ke andar kya-kya hota hai](../01-foundations/01.5-anatomy-of-an-agent.md)

**Ek line mein:** Short-term memory woh hai jo is call ke context window mein pada hai. Long-term memory woh sab hai jo tumhara code model ke bahar store karta hai aur relevant hone par wapas context mein daal deta hai. Jo bhi memory feature tumhe milega, woh in dono mein se ek hoga, ya in dono ke beech information move karne ka tarika.

## 🤔 Yeh kyun zaroori hai?

Lagbhag har [agent](../../GLOSSARY.md#agent) ke saath do complaints aati hain:

- *"Maine kal bataya tha ki main vegetarian hoon, aur aaj isne steakhouse suggest kar diya."* Agent ke paas conversations ke beech koi memory nahi hai.
- *"Lambe task ke beech mein woh bhool gaya ki maine shuru mein kya maanga tha."* Conversation bahut lambi ho gayi, aur shuru ki details kat gayi ya kho gayi.

Dono memory ki problems hain. Lekin dono alag problems hain, aur dono ke fix bhi alag hain. Yeh page dono ko alag karta hai, taaki baaki chapter mein saaf naam use kar sakein.

## 🧠 Idea, simple words mein

Ek busy kitchen ke chef ke baare mein socho.

- Uske saamne ka **counter** chhota hai. Jo abhi us par rakha hai (aaj ke order tickets, is dish ke ingredients), sirf usi se woh kaam kar sakta hai. Yeh hai **short-term memory**: model ka [context window](../../GLOSSARY.md#context-window).
- Peeche ki **pantry aur recipe binder** mein bahut zyada cheezein hain, aur woh saalon tak chalti hain. Lekin chef ko unka fayda tabhi milta hai jab koi sahi dabba ya sahi page laa ke counter par rakhe. Yeh hai **long-term memory**: databases, files ya vector stores jo tumhara code manage karta hai.

[1.4](../01-foundations/01.4-how-llms-work.md) ki do baatein isko clear karti hain:

1. Model [stateless](../../GLOSSARY.md#stateless) hai. Woh calls ke beech kuch nahi rakhta. Woh sirf wahi "yaad" rakhta hai jo tum current request mein bhejte ho.
2. Context window limited hai, aur use bharna free nahi hai. Har [token](../../GLOSSARY.md#token) ka paisa lagta hai. Lambi requests slow hoti hain. Aur context jitna badhta hai, model information ko utna kharab use karta hai. Anthropic ki engineering team is girawat ko *context rot* kehti hai.

Toh:

| | Short-term memory | Long-term memory |
| --- | --- | --- |
| Kahan rehti hai | Request mein: system prompt + messages + tool results | Model ke bahar: database, files, vector store |
| Kitni der chalti hai | Ek call (har baar tum dobara bhejte ho) | Conversations ke paar, jab tak tum delete na karo |
| Size | Context window se limited | Jitna tumhara storage |
| Kaun manage karta hai | Tumhara loop messages append karta hai | Tumhara code decide karta hai kya likhna hai, aur kya recall karna hai |
| Aam failure | Overflow ho jaati hai, ya noisy aur distracting ho jaati hai | Galat cheez recall karti hai, ya purani aur private cheezein |
| Kahan cover hai | [5.2](./05.2-summarisation-and-context-compaction.md) | [5.3](./05.3-vector-memory.md), [5.4](./05.4-episodic-semantic-and-procedural-memory.md), [5.5](./05.5-memory-design-trade-offs.md) |

Ek teesri, chhupi hui kind bhi hai: jo model ne training mein seekha, jo uske weights mein stored hai. Tum use har user ke liye edit nahi kar sakte. Isliye agents ke liye woh fixed background knowledge ki tarah behave karti hai.

## 🔍 Kaise kaam karta hai, step by step

**Short-term memory, ek run ke dauraan:**

1. Tumhara loop [system prompt](../../GLOSSARY.md#system-prompt) aur user ke message se shuru hota hai.
2. Har step model ka reply, koi bhi [tool](../../GLOSSARY.md#tool) calls aur unke results append karta hai ([2.1](../02-the-agent-loop/02.1-the-observe-think-act-loop.md)). Context har step badhta hai.
3. Jab woh bahut bada ya bahut noisy ho jaaye, tum use chhota karte ho: purane turns hata do, unki summary bana do, ya purane tool results clear kar do. Yeh hai [5.2](./05.2-summarisation-and-context-compaction.md).

**Long-term memory, runs ke paar:**

1. **Write.** Decide karo kya rakhne layak hai (koi preference, koi decision, koi seekha hua lesson) aur use save karo. Ya toh turn ke end mein, ya jab model koi "remember" tool call kare.
2. **Store.** JSON file se lekar database ya vector index tak, kuch bhi. Format is par depend karta hai ki tum use kaise dhundhoge.
3. **Recall.** Run se pehle (ya run ke dauraan) jo relevant hai woh fetch karo. Chhote profile ke liye sab kuch, bade store ke liye similarity search ([5.3](./05.3-vector-memory.md)).
4. **Inject.** Recall kiye items ko context mein daalo, aam taur par system prompt ya kisi tool result mein. Ab woh is call ke liye short-term memory ban gaye.

Socho tumhari gali ki kirana dukaan wale bhaiya. Unhe yaad hai ki tum kaunsa doodh lete ho (long-term memory). Jab tum dukaan par aate ho, woh yaad karke wahi packet counter par rakh dete hain (recall aur inject). Aaj tumne kya-kya maanga, woh bas abhi ke liye dimaag mein hai (short-term memory).

[Short-term](../../GLOSSARY.md#short-term-memory)/[long-term](../../GLOSSARY.md#long-term-memory) wala split sabse useful pehla cut hai. [5.4](./05.4-episodic-semantic-and-procedural-memory.md) long-term memory ko aur todta hai, is basis par ki *kis tarah* ki cheez yaad rakhi ja rahi hai: facts, experiences ya skills.

## 💡 Example se samjho

Same travel assistant ke saath do alag conversations. Is assistant ke paas ek vector store ke upar `remember` aur `recall` tools hain ([5.3](./05.3-vector-memory.md)):

```text
SESSION 1: Please remember: my daughter Mia is allergic to peanuts. Also, I always prefer window seats on flights.
  answer: Got it. I'll remember both.
  remember({'fact': "The user's daughter Mia is allergic to peanuts."}) -> 'Saved memory #2.'
  remember({'fact': 'The user prefers window seats on flights.'}) -> 'Saved memory #3.'
  saved 3 memories to agentic-ai-notes-vector-memory.json

SESSION 2 (new conversation, memory loaded from disk): Find me a flight to Oslo next week, and suggest a snack for Mia for the trip.
  answer: I'll look for flights to Oslo with a window seat, and pack a peanut-free snack for Mia.
  recall({'query': 'flight seat preference'}) -> '[0.58] The user prefers window seats on flights.'
  recall({'query': 'Mia snack'}) -> "[0.35] The user's daughter Mia is allergic to peanuts."
```

Information ko follow karo:

| Moment | Short-term memory (context) | Long-term memory (disk par file) |
| --- | --- | --- |
| Session 1, user bolta hai | User ka message, dono facts ke saath | 1 item (signup form se) |
| Session 1, `remember` ke baad | Message + do tool results | 3 items, tool ne likhe |
| Session 2 shuru hota hai | **Sirf** naya sawal: ek message | Ab bhi 3 items |
| Session 2, `recall` ke baad | Sawal + recall kiye do facts | 3 items, koi change nahi |

Session 2 ka context shuru mein Mia ke baare mein bilkul khaali tha. Facts model tak sirf isliye pahunche kyunki agent ne unhe context mein *recall* kiya.

## 💻 Code

Sabse simple long-term memory: facts ki ek JSON file, jo har conversation ke shuru mein system prompt mein load hoti hai. Plain Python plus ek model call:

```python
import json
from pathlib import Path

import anthropic

client = anthropic.Anthropic()  # ANTHROPIC_API_KEY chahiye

MEMORY_FILE = Path("user_facts.json")


def load_facts() -> list[str]:
    return json.loads(MEMORY_FILE.read_text()) if MEMORY_FILE.exists() else []


def save_fact(fact: str) -> None:                       # WRITE: jab user bole "remember ..." tab call hota hai
    MEMORY_FILE.write_text(json.dumps(load_facts() + [fact]))


def chat(question: str) -> str:
    facts = load_facts()                                 # RECALL: yahan, seedha sab kuch
    system = "You are a helpful travel assistant."
    if facts:                                            # INJECT: long-term -> short-term
        system += "\n\nWhat you know about the user:\n" + "\n".join(f"- {f}" for f in facts)
    response = client.messages.create(                   # har baar ek bilkul nayi conversation
        model="claude-opus-5-5", max_tokens=1000, system=system,
        messages=[{"role": "user", "content": question}],
    )
    return next(b.text for b in response.content if b.type == "text")


save_fact("Vegetarian.")
print(chat("Suggest a restaurant for tonight."))         # model apne system prompt mein "Vegetarian." dekhta hai
```

Yeh "sab kuch load karo" wala tarika kuch facts ke liye theek hai. Jab sainkdon facts ho jaayein, tab tumhe selectively recall karna padega ([5.3](./05.3-vector-memory.md)). Aur yeh bhi decide karna padega ki kya likhne layak hai bhi ya nahi ([5.5](./05.5-memory-design-trade-offs.md)).

## 🚨 Aam galtiyan aur dhyan dene wali baatein

- **Chat history ko "memory" bol ke ruk jaana.** Conversation dobara bhejna short-term memory hai. Conversation khatam hote hi woh gayab ho jaati hai, aur woh hamesha badhti nahi reh sakti.
- **Bade context window par bharosa karna.** Ek million tokens ka window bhi bharne mein paisa lagta hai, responses slow karta hai aur context rot jhelta hai. Bade windows problem ko aage khiskate hain; khatam nahi karte.
- **Server-side conversation state ko long-term memory samajh lena.** Kuch APIs tumhare liye conversation store kar sakti hain (jaise Responses API mein OpenAI ke conversation state options). Isse dobara bhejna bachta hai. Lekin yeh ab bhi ek conversation ki short-term history hai, user ke baare mein chune hue facts nahi.
- **Sab kuch "kabhi kaam aayega" soch ke store karna.** Irrelevant memories recall karna model ko waise hi distract karta hai jaise irrelevant history. Soch samajh ke likho.
- **Bhool jaana ki long-term memory logon ke baare mein data hai.** Isko bhi baaki user data jaisi care chahiye: consent, access control aur deletion ([5.5](./05.5-memory-design-trade-offs.md)).

## ✅ Yaad rakhne wali baatein

- Short-term memory = is call ka context window. Long-term memory = jo tumhara code model ke bahar store karta hai.
- Model sirf wahi jaanta hai jo current request mein hai. Long-term memory tabhi help karti hai jab woh context mein recall ho.
- Short-term memory ki problem hai space aur noise (5.2). Long-term memory ki problems hain kya likhna hai aur kya recall karna hai (5.3 se 5.5).
- Har long-term memory system ke chaar same steps hote hain: write, store, recall, inject.

2. Upar wale example mein session 2 ek single message se shuru hota hai. Mia ke baare mein facts model ke context mein exactly kahan aate hain?
